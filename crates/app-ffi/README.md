# Phone bridge

`app-ffi` is the C ABI the iPhone app calls. It hosts two crates:
`app-embedded`, the daemon's profile runtime running in the app's own process
(its store of replica rows, identity, pairing and relay link), and
`app-runtime`, the chats and fleet over that runtime. Nothing outside this
crate knows a C type exists; the header is generated by cbindgen into the
build's `OUT_DIR` as `amux_app.h`.

## Values

Everything crosses as JSON. The Swift mirrors of every value are generated
from the Rust definitions into
`apps/apple/Packages/AmuxCore/Sources/AmuxValues/Values.swift`:

```sh
cargo run -p xtask -- swift-types          # regenerate
cargo run -p xtask -- swift-types --check  # fail when the committed file differs
```

Rows, ask cards, the strip and fleet cards are the `ui-view` values the
terminal renders; `ChatFrame`, `ChatChanges`, `Draft`, `RowOptions`,
`HostView` and the act outcomes are `app-runtime::values`. Byte strings such
as agent and input ids are JSON arrays of numbers. Answers never carry a
provider's answer body: the phone names a choice by its position on the
card, or gives one `Pick` per question, and the answer is built in Rust.

## Lifecycle

```c
AmuxRuntime *rt = amux_runtime_start(config_json, wake, context, &error);
AmuxChat *chat = amux_session_open(rt, agent_key_json, 0, &error);
...
amux_session_close(chat);
amux_runtime_stop(rt);
```

`amux_runtime_start` takes a `StartConfig` and blocks until the store is
open and the fleet has caught up. `amux_session_open` blocks until the
chat's snapshot and the rows this device holds are applied, so the first read
is correct even with the agent's host away. Close every chat before stopping
the runtime.

## Reads and changes

Reads return at once: `amux_session_keys`, `amux_session_rows_for`,
`amux_session_ask_card`, `amux_session_strip`, `amux_session_frame`,
`amux_fleet_rows`, `amux_fleet_card`, `amux_fleet_family`, `amux_fleet_hosts`.

Rows are handed out by item key, which never moves. The host's id sequence
only grows at its two edges: `amux_session_new_keys_above(chat, newest)` for
rows that arrived after the newest it holds, and
`amux_session_new_keys_below(chat, oldest)` for a page of older ones. Either
returns JSON null when the key it names is no longer held, and the host reads
`amux_session_keys` again.

The wake is called on a worker thread with a chat's id, or 0 for the fleet,
whenever that one moved, and at most once until the host takes its changes
with `amux_session_take_changes` or `amux_fleet_take_changes`. However many
updates land in between, the host is woken once and takes every changed key
together. It schedules the take on its main thread and returns; it never
does the work in the wake.

## Acts

Acts that wait on the agent take a callback, called once on a worker thread
with a JSON result the callback borrows until it returns:
`amux_session_send`, `amux_session_answer` (by choice index),
`amux_session_answer_questions`, `amux_session_withdraw`,
`amux_session_send_now`, `amux_session_resend`, `amux_session_interrupt`,
`amux_session_resume` (the exited composer's draft), `amux_session_page_older`,
`amux_session_put_blob`, `amux_runtime_pair` (a PIN or a pairing link),
`amux_runtime_unpair`, `amux_runtime_sign_in`, `amux_runtime_sign_out` and
`amux_runtime_dump`. `amux_session_discard` forgets a not-confirmed input at
once.

`amux_runtime_set_source_policy(rt, listed)` keeps a source open for every
listed agent in the foreground, and only for the chats that open when a push
wakes the app in the background.

## Ownership

Every returned string is the caller's to free with `amux_string_free`, and
every `AmuxBytes` with `amux_bytes_free`. A null return means the call
failed; a panic inside the library is caught at the boundary and reads as a
failure. The `debug-tools` feature, which only driving builds carry, lets
`StartConfig.lan_bind` keep direct links on loopback.

## Tests

`cargo test -p app-ffi` drives the C functions against a desk served in
process: pairing by PIN, the fleet, a chat's rows by key, a permission
answered by position, a question answered with picks, paging and a dump.
`cargo test -p app-runtime` covers the wake-once coalescing and the chat
views; `cargo test -p app-embedded` covers pairing on the local network and
sign-in with pairing through the relay.

`just ios rust` builds the simulator slice with `debug-tools` and packages it
as `target/ios/AmuxAppDebugTools.xcframework`; `just ios package` builds every
shipping slice into `target/ios/AmuxApp.xcframework`.
